# Design

Why the language in [language.md](language.md) looks the way it does, and the Step Functions and JSONata behavior the compiler relies on.

## Principles

1. **The product is the ASL.** sfnx is for people who find ASL tedious or hard to write. It stops at the definition and at checking it: running a definition locally with mocked tasks is part of checking it, while deploying it and running it in AWS belong to other tools.
2. **The Python should run, but the contract is with the ASL.** The output is what someone writing ASL by hand would write for the intent of the source, not a reproduction of Python: `str(True)` is `"true"`, while a comprehension is a list for any number of results, as its author means. Known differences from CPython are listed in [Where results differ from Python](language.md#where-results-differ-from-python); others may remain.
3. **No hand-written library.** The names sfnx exports make states (`state_machine`, the operations of `aws`, `activity`, `task`, `wait`, `parallel`, `inline_map`, `distributed_map`) or name what ASL names (`context`, error classes, and `jsonata` for an expression written out). The operations and errors of `aws.sdk` come from botocore's models, not from a wrapper written for each service. ASL settings such as `Arguments`, `ItemReader` and retriers are passed through as the structures they are, with no builders.
4. **As few control structures, operators and built-ins as the flows need.**

A construct is accepted when ASL or JSONata has a counterpart for it and its meaning can be written as a JSONata expression. The meaning is mapped, not the operator: JSONata has conditionals and arithmetic, so `a or b` is `a` where it is true and `b` otherwise, and `a % b` is `$a - $b * $floor($a / $b)`.

**What a spelling guarantees.** Following the intent of the source comes to this: a spelling the compiler accepts follows Python for the values that reach it. Where the JSONata that reads most naturally would quietly give another value, the longer expression that does not is written instead, and where the source itself holds a value Python would refuse, the file does not compile. What is left is listed in [Where results differ from Python](language.md#where-results-differ-from-python) under the reason it stays: JSON has no such value, Step Functions reads text and time its own way, the value or the type is only known when it runs, the ASL takes more than Python does, or the spelling was chosen to mean something else. Declaring a type is what shortens an expression that has to test one, and `jsonata()` writes what has no spelling here at all.

## Types

**Why types at all.** Someone writing JSONata by hand knows the type of each value and picks the spelling from it: `$a + $b` for numbers, `$a & $b` for strings, `$append($a, $b)` for arrays. Python's `a + b` can be any of the three, and the compiler never sees a value; the input arrives with `StartExecution`. So the source states what the hand-writer already knows, where it matters.

**Only where an operation depends on it.** `+`, `len`, `in`, a variable key and `for` need a type. `-`, `*`, `/`, comparisons, `and` / `or` / `not` and literal keys have one spelling and need none. One known side is enough, since Python's `+` requires both sides to agree (`input["name"] + "!"` is a string join). Only the leaf that is operated on needs an annotation (`total: float = input["order"]["total"]`).

**A TypedDict states the shape once.** Someone writing a workflow by hand knows the shape of its input, and a type checker wants it stated too. A TypedDict class of the module states it in one place, and the compiler reads the same class the type checker reads, without running the module, as it reads exception classes. It is the object type with named fields that an AWS response already has from its botocore shape, so nothing new is needed to type what is read under its keys. `NotRequired` and `total=False` keep their meaning for the type checker: a key that may be missing, read with `in` or `.get()`, not a value that may be `None`.

**An annotation is a claim.** It generates nothing and is not checked at run time: Step Functions has no input schema, and a wrong claim fails with `States.QueryEvaluationError`, as hand-written JSONata would. `float(x)` is the conversion. There is no `Any` or `object`; a value passed through untouched needs no type.

**Narrowing follows type checkers.** `isinstance`, `is None` and `is not None` narrow in branches, in the right side of `and` / `or`, in conditional expressions and after a branch that returns. A declaration belongs to the name, as in PEP 526, so after branches it holds as the types of the branches that declare it. A test trusts the run time over a declaration: `isinstance(x, list)` on a value declared `str` types the branch as a list.

**Task results.** botocore's output shapes type SDK and optimized integration results (structures with PascalCase keys, lists, maps, strings, numbers and booleans; blobs and timestamps are unknown). What external code returns is unknown: a Lambda `Payload`, a `.sync:2` child's `Output`, an activity's result, an HTTP `ResponseBody`, and every result of `.sync` and `.waitForTaskToken`.

## Decisions

**A decorator marks the machine.** A rule such as "every top-level function is a machine" is shorter, but invisible: a shared helper would silently become a machine. The decorator returns the function, so the module still imports. It takes only `timeout`, the one top-level ASL field a user decides; the workflow type, logging, tracing and the role belong to the deployment.

**The parameter reads `$states.context.Execution.Input`.** `$states.input` is the input of the current state and becomes the result after a Task, Parallel or Map, so spelling the parameter by where it is read would make one `input["amount"]` look two ways. Assigning to the parameter is rejected: after a branch it would be unclear which of the two it names. The name `input` in examples follows `StartExecution` and `$states.input`.

**State names come from what a state does.** The variable, `return`, `if`, the action of a Task. Line numbers would rename every state when a line is added above, breaking mocks keyed by state name and turning every change of the generated ASL into a change of every line. Serials count across the whole definition, since Step Functions wants names unique there, and states in a branch or a Map carry the name of the function that holds them, which `Branches` has nowhere else to keep.

**States split only where ASL requires it.** `Assign` evaluates every expression with the values from before the state, so an assignment that reads a pending one reads its expression instead, as a hand-writer spells the path out again, except where the expression would give another value when read again (the time, a random value, a `jsonata()` expression that is not settled, which may read variables by name) and where a name is assigned again, whose first value Python still evaluates; those need a new state; a Task is one state per call; a Choice is one state. A name assigned again shares the state where the new value reads the first where JSONata always evaluates it, such as the test of a conditional expression, and the first can never be undefined (a value written in the source, a variable, or `d.get()` with such a default): undefined fails an `Assign` but passes through a test such as `$type()`, so a key that is missing would otherwise give a value where Python fails. A first value that can neither fail nor be undefined, such as one written in the source, leaves Python nothing to evaluate, so the new value takes its place in the same state wherever it reads the first. An `if` whose every branch assigns one variable and nothing else is that variable's conditional expression (`v = a if test else v`), as a hand-writer writes `test ? a : v` in an `Assign` instead of a Choice, unless a branch gives it a value written in the source and the function tests it elsewhere against such a value, which a Choice decided by known values can then drop. Everything else shares a Pass, a Task's result goes in its own `Assign`, and a machine that returns a Task's result ends on it. A `return` right after assignments that no Task, Parallel or Map holds is a Succeed whose `Output` reads them as their expressions, as a hand-writer returns what they compute, since nothing reads them after it: Python evaluates each even when the `return` does not read it, so each neither fails nor is undefined, or the `return` is that variable itself, whose `Output` fails where the Pass would; one that changes on evaluation keeps the Pass. A `raise` right after such assignments is a Fail alone where none of them can fail, be undefined or change on evaluation: nothing reads them after it, and its message reads them as their expressions. So do the assignments right after a Task, a Parallel or a Map, in its `Assign`, the step of a `for` loop whose body ends with one among them, which reads only the counter no Task assigns, and the start of a `for` loop right after one where it reads nothing the state assigns, which reads the same there, and a `return` after them or right after the state, as its `Output`: they read the result the state assigned as `$states.result`, the variables assigned before them in the same `Assign` as the expressions those take, and the other variables from before the state, as the Python reads them. Where the `Assign` or the `Output` could fail otherwise than a Pass or a Succeed would, those stay: a Catch would take the failure and a retrier for `States.ALL` or `States.QueryEvaluationError` would run the state again (measured), so the statements after such a retrier keep them. Inside a `try`, Python's `except` takes that failure too, and a Pass would let it end the execution, so they go in the `Assign` and `Output` of the Task, the Parallel or the Map before them, whose Catch takes a failure of either (measured for each; corpus: `catch-takes-a-failure-folded-into-a-parallel`, `catch-takes-a-failure-folded-into-a-map`), when they are in the same `try` bodies as that state; a statement after the `try`, which only the state leads to when every `except` clause ends, is not in their reach. A failing `Assign` assigns nothing, the state's result included (measured; corpus: `failed-assign-assigns-nothing`, `except-reading-the-result-keeps-the-pass`), where Python keeps what the statements before the failing one assigned, so they keep their Pass or Succeed where a way on from the catchers reads a variable the state or they assign before a statement that holds an expression, which may fail. A variable assigned only after each such statement holds its value from before the state on those ways in both, as Python had not assigned it yet when the statement failed; a value written in the source does not fail. None of this holds back statements in which nothing can fail or be undefined (variables, paths, literals, `$exists()`, `$type()`, `$not()`, `$boolean()`, `$count()`, `$keys()`, `$append()` (measured), `=`, `!=`, `in`, `and`, `or`, conditionals, `d.get()` with such a default, and lists, dicts and comprehensions of them): a failure of the `Assign` is then the state's own, which assigns nothing in Python either, and the Catch has nothing of theirs to take, so they go in the state after the `try` too. After a Parallel or a Map, those that read the time or a random value keep their state, as when those are read there is not measured. They read the variables the state assigns as the expressions it assigns them, a longer one read more than once bound to the variable's name first, as a hand-writer binds it, so they keep their state where a string in them spells such a variable, as the text of `jsonata()` may, which is not a read. A `States.TaskFailed` retrier does not match a failing `Output`, a Task's or a Map's (measured; corpus: `task-failed-retrier-misses-a-failing-output`). A value that reads the context's `State`, which names the state it is read in, or a `jsonata()` expression that is not settled keeps its Pass or its Succeed too. A `return` of a value written in the source has no expression to fail, so it is the `Output` wherever the state is last, a Catch or such a retrier notwithstanding, and where paths join before it, each Task, Parallel or Map on a way to it ends with it, which saves the transition to the Succeed the other ways still take. Assignments of values written in the source go in the `Assign` of such a state for the same reason, as a hand-writer assigns a status in a Task and in its catcher. The time and a random value do not: the `Assign` and the `Output` of a Task run when it ends, and a Wait's `Assign` when the wait is over (measured), where Python reads them after the call or the wait. A Parallel's and a Map's are not measured, so there they keep theirs. The `Output` and the assignments that go in the state read such a value as its expression only where they read it once: each `{% %}` is evaluated on its own (corpus: `volatile-read-twice-keeps-its-state`), and `$random()` and `$uuid()` give another value every time, so what reads it twice reads the variable in a state after it. A `return` right after a Wait is its `Output` and `End`, evaluated when the wait is over as the `Assign` is (measured), where Python returns after `wait()`. Assignments right after a Wait go in the Wait's `Assign` when only the Wait leads to them, and those that start a branch of an `if` or the body of a `while` or a `for` go in the Choice rule that leads there, or the Choice's own `Assign`, which applies only when no rule matches (measured), for `else`, for what follows an `if` whose branches all end, and for what follows a loop left without `break`, which only the `Default` leads on to. Where paths join, the assignments that follow are copied into the `Assign` of the last state or Choice rule on each path, as a hand-writer copies an assignment into each branch, when each can take them and assigns no name they read or assign, so they read there what they would read after it. They read the same variables there, and a Wait and a Choice have no Catch, so a value that fails ends the execution either way. A Wait's `Assign` is read after the wait (measured), so it takes the time and a random value as Python reads them after `wait()`; a `jsonata()` expression that is not settled and the context's `State` keep their Pass. Right after an `except` clause's catchers, which assign the error, the assignments read it as `$states.errorOutput`, the expression the catchers assign it, as the assignments after a Task read its result as `$states.result`. A Choice whose `Default` leads only to another Choice takes that one's rules after its own, as a hand-writer lists the tests of consecutive `if` statements in one Choice; the first's own `Assign`, which runs on its `Default`, goes in each rule taken over. Where any rule or `Default` leads straight to another Choice, the first takes the second's tests in its place, `a and b` for a rule `a`, and the second stays for the other ways into it. The second's tests read what the transition assigns as the expressions it assigns them: the first Choice evaluates its tests and the transition's `Assign` with the same variables and the same input (corpus: `choice-taken-in-reads-what-the-rule-assigns`, `choice-taken-in-reads-the-value-from-before`), so the expression reads there what the variable would hold in the second, and the transition's `Assign` goes on each way out, so a value that fails still fails the Choice, with another state named in the Cause. Only an expression that gives another value each time it is evaluated reads otherwise, as the test would evaluate it apart from the `Assign` that keeps it: the time, a random value and `$eval()`, which a `jsonata()` expression may call; its text is read for them. JSONata's `and` and `or` evaluate no more once the first side decides (measured; corpus: `volatile-short-circuit`, `choice-taken-in-is-not-evaluated-past-a-false-test`), so a test reached only through `a` is evaluated only where `a` holds, as in the second Choice. The second's `$states.context.State` names the state it is read in, so a Choice that reads it keeps its own. The rules repeat the transition's `Assign`, which is how a hand-writer who lists the tests in one Choice has to write it, so a Choice that starts a Map processor with many assignments grows by a copy of them for each rule taken in. A Choice that leads back to itself through Choices alone is taken in once into each Choice, as each copy of its rules leads to it again. Python has no goto, so a path that should continue elsewhere, such as a saga's compensation for the stage that failed, is written with a flag and the `if` statements that test it. The value a flag holds on each path is written in the source, so where every way into a Choice gives the flag the same such value, the test is decided there and that way leads where the test sends it (corpus: `catch-sets-the-flag-a-choice-tests`), as the Catch of a hand-written saga leads to its compensation. The values are followed through the definition until they settle, and `=` compares as JSONata does, the same type and value. `<`, `<=`, `>` and `>=` are decided between numbers only, as JSONata orders strings by UTF-16 units where Python orders them by code points; so a loop that starts from `attempts = 0` goes straight into its body, as a hand-writer's first call does, and only the way back tests the count. The `Assign` of the rule or the `Default` a path skips goes in the transition that skips it, which evaluates it at the same point with the same variables; a failure there ends the execution as it would in the Choice, a catcher's included, which neither a later catcher nor a retrier takes (measured), so a Task, a Parallel or a Map takes it only as above. It stays in its Choice where it reads `$states`, which is another state's in the transition, or a name the transition assigns, which it would read before it is assigned. The assignments that start a machine, a branch or a Map processor have nothing before them to hold them, and a hand-writer assigns what the input gives in the first state, so they go there: in a Choice's rules and its own `Assign`, which between them run on every path, or in a Task's `Assign` where its failure would end the execution, as after a Task. Where none of them can fail or be undefined, a Wait, a Parallel or a Map takes them too, in its `Assign` and its catchers', as none then fails after the state has run; the branches or the processor, which run before that `Assign`, read only values written in the source, which read the same in a child execution of a distributed map, whose context is its own. A Choice they decide, as `if x is None` right after `x = None` is, is skipped first, as elsewhere where values written in the source are known, and where that leaves a `return` right after them and none of them can fail or be undefined, the `return`'s `Output` reads them. The state reads each as its expression, since its `Assign` evaluates with the values from before it, and the input it reads is the one the Pass would have read, as a Pass without `Output` passes its input on. Values that read the time, a random value, a `jsonata()` expression that is not settled or the context's `State` keep the Pass. Moved into a Task, a value the input lacks fails after the call rather than before it, which the table of differences lists.

**A name outside the machine is written in.** ASL has no name for a value: a Retry is repeated state by state, and every Task writes its own Arguments. Python has the name, so a name assigned at the top level of the module is read as the value written there and put in at each place it is read, and the definition reads as it would if the value had been written out. The compiler reads the module without running it, so such a name holds data and exception classes; `NOW = time.time()` is rejected where it is read, because writing it in would evaluate it state by state instead of once at import. A machine that assigns the name has a variable of its own, as Python does, and a variable inside the machine is what writes a value into the definition once.

**A name ASL cannot use as a variable is renamed.** Step Functions variable names do not start with `_`, and `$states` is reserved. A variable also hides the JSONata function of its name, and a definition that calls the function then fails only when it runs. Someone writing ASL by hand would pick another name, so sfnx does the same instead of rejecting the Python name: the leading `_` is dropped (`$tmp`), and `states` and a name the generated expressions call as a function get `_val` (`$count_val`). The new names are chosen for the whole module at once, numbered past every name it uses and every name already given, and state names keep the Python name. Only those names change, so the rest of the definition reads as written.

**`jsonata()` covers what Python does not.** The functions and methods with a Python spelling are those a workflow reaches for often; the rest of JSONata stays reachable through one name instead of a Python spelling each. The values go in by name and are bound at the start of a block, because a Python variable does not always keep its name in the definition (`count` is `$count_val`, a loop's item is `$items[$item_index]`), and the text of the expression stays as it is written.

**Dividing by zero is tested where Python would raise.** JSONata has no error for it: `$a / 0` gives the string `"Infinity"`, which fails only in a later state that does arithmetic on it, and compares as a string without failing, so a Choice takes a branch on a value Python would never have produced (measured). A divisor that is not written as a number is therefore tested first, `$b = 0 ? $error('division by zero') : $a / $b`, so the execution fails where it divides, with `States.QueryEvaluationError` and `division by zero` as the cause. A divisor written as a number needs no test, so `$a / 1000` stays as it is, and one written as zero is rejected when the file is compiled, as is one that comes to zero as the file compiles: `+`, `-`, `*`, `//` and `%` of integers written in the source, their comparisons, `+` of strings or of lists, and `==` and `!=` of strings, are written as their value, as a hand-writer writes `86400` for `24 * 60 * 60`. The integers stop at 2^53, past which a double rounds them where Python does not. `$error` is a function the generated expressions call, so a variable of that name is renamed as the other function names are.

**A value that changes on evaluation is evaluated once.** Some Python operations have no single JSONata spelling and write an operand twice: `a % b` is `$a - $b * $floor($a / $b)`, `a < b < c` is `$a < $b and $b < $c`, `a or b` as a value reads `a` for its truth and then reads it again, `a is not None` is `$exists($a) and $a != null`, and `d.get(k, x)` tests the value before reading it. For a variable or a field that is what a hand-writer does. A test that reads its value three times, as the truthiness of a value of unknown type and `int()` do, binds anything longer than a variable, to keep the expression readable rather than to keep it from changing. For `$random()`, `$uuid()`, `$now()` and `$millis()`, and an expression built on one, the two readings would differ, so such an operand is bound first in a block, `($v := $random(); $v - 3 * $floor($v / 3))`, under a name that hides nothing the block reads. A `for` over such a list, or a `range()` to such a stop, copies it before the loop for the same reason, as does `a, b = ...`, where every name reads the value again. An expression written in `jsonata()` is not parsed, but every `$name` in its text is read: it is settled, a value like any other, where each one is a function it calls or passes, a name the call binds, or a name it binds itself (a lambda's parameter, or `:=`) that no variable in scope has, and none is `$random`, `$uuid`, `$now`, `$millis`, `$eval`, `$states`, `$` or `$$`. A call written `$random ()`, or made under a name the expression binds the function to, still names `$random` in the text, so looking for the name finds it however it is called. An expression that is not settled counts as changing, and one that holds still is bound too, and a `for` over one copies it before the loop, as an unpacked one does. A `$` in a string or a regular expression is taken for a name, which only keeps an expression from being settled. The name bound avoids every `$name` the code holds, since an expression written by hand names variables the program never declared.

**Comments come from the source.** `Comment` is the only documentation ASL keeps, and a docstring or a comment above a line is where a Python author already writes it. Taking what is there needs no new syntax, and a comment that should stay out of the definition goes where it is not taken, after the code or above a blank line.

**Control flow is statements, not functions.** One ASL scope is a flat graph with jumps; `if`, `for` and `while` can produce any of it, while functions and closures only produce trees.

**Every spelling is one Task.** A Task varies only in its `Resource` and `Arguments`, so each way of writing one makes the same Task, checked the same way. `aws.sdk.<service>.<operation>(...)` and `aws.optimized.<service>.<operation>(...)` name the resource as its ARN does: the service by its ARN name, and the operation in snake_case, which botocore maps to the action of an SDK integration and which is joined in camelCase for an optimized one, as botocore has no model of those. The API parameters are keyword arguments. Step Functions writes them in PascalCase, even for APIs whose parameters are camelCase, so they never collide with the Task's own settings, which are lowercase: `timeout=`, `heartbeat=`, `role=`, `retry=` and `pattern=`, the integration pattern that ends the ARN. A dict unpacked with `**` is merged in, and one unpacked on its own is the `Arguments` as it is. `activity(arn, input)` takes the input as a dict, as a worker's input has no parameter names. `task(resource, arguments)` writes the ARN out, for a resource that is not an operation of a service, such as `${...}` or a Lambda function's ARN, and for arguments whose keys are not identifiers. sfnx ships no type stubs for the operations, which would run to some 19,000 methods, so a type checker does not know them; the compiler checks them, as it checks an ARN.

**A statement holds one state-making call, where it always runs.** Not in a condition, a comprehension, a branch of a conditional expression, the right side of `and` / `or` or a later operand of a chained comparison, since the Task would run whether or not that part is taken.

**Branches and map functions are nested functions.** An ASL branch reads the variables around it and cannot write them, and has its own locals and `return`; a Python nested function matches on all four. Step Functions rejects an inner scope that assigns a name its outer scope assigns, where Python keeps the two apart, so such a name is numbered in the inner scope, as a loop's counter is. As in Python, a name the function assigns is local to it from its first line. `Map.Item` is readable only in the `ItemSelector`, so an inline map passes the item by parameter name and binds it in the first Pass when a state after the first reads it, where `$states.input` has been replaced, or the function assigns the parameter again. The first state reads `$states.input` as the item in its `Arguments`, `Assign`, `Output` and catchers alike (TestState with a mocked result; measured), and so does the first state of a branch of a Parallel that is first, whose input is the Parallel's. A distributed map runs child executions that read nothing outside, so values reach them through `args=`, which the `ItemSelector` or `BatchInput` evaluates in the parent.

**A function called directly is written in place.** ASL has no subroutine: a Task runs where its state is, and a helper that makes one has to be states at each place it is used. Compiling the body at each call writes what someone copying the states by hand would, so the definition keeps its shape and the source loses the repetition. A parameter reads the argument as written, since a Resource ARN and a Retry exist only written out in the definition, and binding every argument to a variable would add a Pass to each call for values that do not change; one that changes on evaluation is kept once, as elsewhere. The names the body assigns are the function's own, as in Python, so one the caller uses too is numbered. A module function reads the module's names, which the caller's variables would hide once the body is written in the caller, so that case is diagnosed. The call is a statement's value, where a `task()` can be, because the body can add states and a `return` in it has to end the path it is on.

**`try` puts a Catch on each state that can fail.** Wrapping the body in a one-branch Parallel would hide the variables assigned before the failure and need detours for `break`, `continue` and `return`. Only Task, Parallel and Map can catch, so a `try` with none of them is rejected. A Fail ends the execution, which no Catch in the same scope takes, so a `raise` that an enclosing `except` catches is a way into that clause instead, as a hand-writer leads a Choice's rule straight to the cleanup: the clause's variable is assigned what a catcher would assign, in the rule or the state before the `raise`, and no Fail is written. A bare `raise` in a clause stays a Fail, so one that Python would catch in an enclosing `except` is rejected.

**Errors are classes, with no hierarchy.** `except` takes classes, so retriers take the same classes. ASL error names are flat, so a class derives from `Exception` directly and `except (A, B)` lists several. A nested class spells a dotted name (`Lambda.ServiceException`), which Python class names cannot hold otherwise. A segment that starts with a digit, which a Python class name cannot, is written with a leading `_` that is dropped, so `_416` spells `416`; a `_` before a name that stands on its own stays, since ASL takes `_Internal` as it is. Built-in exceptions have no ASL name and are rejected. `Exception` stands for `States.ALL` in an `except` and a retrier, and cannot be raised, as it names no single error.

**Retries are per state.** A retrier is a JSON object, written as a dict. There is no machine-wide default, and no new syntax for retrying several steps: `parallel(f, retry=[...])` produces the one-branch Parallel ASL offers for it.

**A `for` loop counts.** It keeps an index and reads `$items[$item_index]` instead of a Pass per iteration, since in a Standard workflow every state transition is billed and counts toward the history limit. When the body changes what the loop iterates, the loop copies it first, as Python iterates the original. A loop is compiled again with wider types until the types at its head hold for every way back to it; a type that grows on every way back (`x = [x]`) becomes unknown after a few attempts. The loop variable ends with the loop, as a counter would otherwise leave a value Python does not. `enumerate` gives the counter the writer's name, so the body cannot assign it; `zip` shares one counter between two lists and stops at the shorter, as `$zip` does; and `d.items()` counts the keys and reads each value with `$lookup`.

**Comprehensions are `$map` and `$filter`, kept as lists.** Without brackets one result would be a value and no result undefined. Brackets would merge a single result that is a list, so when the items may be lists the result is `$append([], $map(...)[])`: `[]` keeps a single result as an array, and appending it to an empty array turns no result into `[]`. A `$filter` whose items may be lists gets `[]` too before `$map` iterates it.

**A dict comprehension is one pass, merged.** `$merge` of the one-key objects a `$map` returns is the dict, a later key winning over an earlier one as a later entry does in Python, and `$merge` of nothing is `{}`, so nothing has to be wrapped or appended around it. The condition stays inside the function (`c ? {k: v}`) instead of going into a `$filter` before it, so that the key and the value are read only for an item the condition kept, in the order Python reads them; a `$filter` first would read every condition before any key, which is what a list comprehension does. The key goes into a JSON object, so it must be known to be a string: `$string` of an unknown type would write `1` and `"1"` as one entry where Python has two, losing a value rather than converting it, so such a key is rejected and `str(x)` is written instead. `d.items()` reads the dict itself rather than its keys, as the `for` loop over it does: `$sift` where the entries pass through as they are, and `$each` where the key or the value is rewritten.

**`any` and `all` fold with a conditional.** `$count($filter(...)) = 0` would read every item, while Python stops at the item that decides the result and evaluates nothing after it, so a generator expression whose later items would fail still gives an answer. The two compile to a `$reduce` whose function is a conditional, `$a ? true : <item>` for `any` and `$a ? <item> : false` for `all`: once the result is decided, the branch holding the item is not the branch taken, and a generator expression's condition sits in the same place. `$reduce` still visits every item; what this promises is that nothing past the deciding item is evaluated, not that the array is left half-read. An empty array gives the initial value, which is what Python gives for one: `False` for `any` and `True` for `all`. A list comprehension written in the call (`any([f(x) for x in xs])`) is built before the fold reads it, so every item is evaluated there, as in Python.

**Lists keep their shape.** JSONata's array constructor merges the items of an array value unless the item is itself written as an array constructor, so `[xs]` of a list would lose a level. An item known to be a list is wrapped once more (`[[$xs]]`), and one that may be a list is tested when it runs. `xs += [...]` is rejected because Python extends the list in place, which other names for it see, and a JSON value is a copy.

**The Context Object is read by subscript**, like the input, with the keys ASL uses. The fields readable only in some places are diagnosed: `Task.Token` outside the arguments of a `.waitForTaskToken`, `.sync` or `.sync:2` Task, and `Map.Item` everywhere. A `.sync` and a `.sync:2` Task have a token in their `Arguments` and `Assign`, where a request-response Task has none, though ValidateStateMachineDefinition takes a read of it in any Task and rejects one only in a Pass (measured).

## What the compiler relies on

From the Step Functions and JSONata documentation, from [jsonata-python](https://github.com/rayokota/jsonata-python), and from Step Functions itself where noted (TestState, ValidateStateMachineDefinition and executions, measured on 2026-09-13, 2026-09-14, 2026-09-18, 2026-09-22, 2026-09-23, 2026-09-24, 2026-09-25 and 2026-09-26).

### JSONata in Step Functions

- Step Functions implements JSONata 2.0.6 without `$eval`, and adds `$partition`, `$range`, `$hash`, `$random`, `$uuid` and `$parse`. An expression has a one-second limit and a memory limit; every failure is `States.QueryEvaluationError`.
- An expression that returns undefined fails, in any field and inside objects, arrays and `Assign` (measured).
- A function is not a value: an expression that returns one, alone or inside an object or an array, fails with `States.QueryEvaluationError` ("returned an unsupported result type") in `Assign`, `Output` and a Choice's `Condition` alike (TestState; measured). A JSONata function is used only inside the expression that defines it.
- `Assign` evaluates all its expressions with the values from before the state, then assigns. `Assign` and `Output` of a state are evaluated in parallel.
- Binding a variable hides the built-in function of the same name (`count` hides `$count`), and ValidateStateMachineDefinition does not report it: calling the function fails when it runs (`T1006: Attempted to invoke a non-function`; measured).
- `and`, `or` and `$not` convert operands as `$boolean` does and return booleans. `$boolean` matches Python's `bool()` except on a non-empty array whose items are all falsy (`[0]`, `[[]]`), which is false (measured).
- With undefined, both `=` and `!=` are false.
- `$count` counts a non-array as one item, and null or a missing value as zero.
- `$s[0]` of a string returns the whole string; `$substring` and `$length` work on strings. A fractional position is truncated (`$x[1.5]` is `$x[1]`).
- `$toMillis` reads the ISO 8601 form `$now()` returns: it counts a timestamp with no UTC offset from UTC and keeps whole milliseconds, while a space in place of the `T`, a form without the dashes and a week date fail. `$fromMillis` returns the form `$now()` does, and `$toMillis($now())` is `$millis()`, so the two spellings of the current moment agree. It drops a fraction of a millisecond towards zero, with or without a picture: `$fromMillis(1.6)` is `1970-01-01T00:00:00.001Z` and `$fromMillis(-1.5)` is `1969-12-31T23:59:59.999Z`, as in jsonata-python (measured).
- A position right after a variable position has no effect (`$x[$i][0]` returns `$x[$i]`; `($x[$i])[0]` works; measured).
- `&` joins non-strings as strings (`'a' & 1` is `'a1'`). A string literal has no `\'` escape.
- An array constructor merges the items of an array value that is not itself a constructor: `$count([$xs])` of `[1, 2]` is 2, and `[[$xs]]` and `$type($x) = 'array' ? [[$x]] : $x` keep one item for arrays, scalars, objects, one-item arrays, nested arrays and null (measured).
- `$map` and `$filter` return a value for one result and undefined for none; in brackets they are `[2]` and `[]`, but a single array result loses a level. `$map(...)[]` keeps a single result as an array (but not in parentheses, `($map(...))[]`), and `$append([], $map(...)[])` is `[]` for none; for 0, 1 and several items, lists and nested lists, with and without `$filter`, CPython, jsonata-python and Step Functions agreed (measured).
- `a % b` as `$a - $b * $floor($a / $b)` matches Python for negative operands; `$power` matches Python's `**` except for a negative base with a fractional exponent, where JSONata fails (measured).
- Dividing by zero does not fail: `1 / 0`, `-1 / 0` and `0 / 0` are the strings `"Infinity"`, `"-Infinity"` and `"NaN"`, and so is `$floor` of them. Arithmetic on them fails, but a comparison does not (`1 / 0 > 5` is true; measured).
- Numbers are doubles. A literal number in the definition keeps its digits, but read in an expression, from a variable or the input, an integer past 2^53 is rounded (`10000000000000000000000001` is `1.0E25`; measured). `+`, `-`, `*` and `/` past the range of a double give `"Infinity"` or `"-Infinity"` as division by zero does, and `$number` of a string past it fails (`"1e400"`; measured).
- `? :` binds looser than `and` and `or`.
- `$merge` of an array of objects gives a later object's key precedence over an earlier one's, null values included. An array among the items is merged as its objects, as the array constructor merges it, and `$merge([])` is `{}` (measured).
- An object constructor takes an expression as its key, and evaluates the key before the value. `$map` and `$each` leave out an item their function returns nothing for, which `c ? {$k: $v}` does where `c` does not hold. `$sift` keeps the entries its function is true for and returns nothing when it keeps none (measured).
- `$parse` fails on text JSON does not allow (`NaN`, `Infinity`), on a number past the range of a double (`1e400`) and on a repeated key, but reads single-quoted strings (`{'a': 1}`; measured).
- `$uuid()` returns a new lowercase version 4 UUID on every call (measured).
- `$now()` returns the time in UTC to the millisecond with a `Z` (`"2026-09-15T13:36:42.245Z"`), `$now('[Y0001]-[M01]-[D01]')` formats it with a picture string, and `$millis()` returns the milliseconds since 1970 (measured). Every `$now()` and `$millis()` in one evaluation of an expression returns the same time.
- The picture components `[Y0001]`, `[Y01]`, `[M01]`, `[D01]`, `[H01]`, `[m01]`, `[s01]` and `[d001]` write the year, the last two digits of the year, the month, the day, the hour, the minute, the second and the day of the year, each padded to the width the component gives, which is what CPython's `%Y`, `%y`, `%m`, `%d`, `%H`, `%M`, `%S` and `%j` write for the same moment in UTC. In the text between components `[` and `]` are written `[[` and `]]`, `%` needs no escape, and a picture holding no component is returned as it is (measured). jsonata-python writes each of them the same way, so `sfnx.testing` keeps the function.
- `$formatNumber` rounds half to even on the decimal the number is written as, not on the double it holds: `$formatNumber(0.125, '0.00')` is `0.12` and `$formatNumber(2.5, '0')` is `2`, as CPython's `format()` writes them, while `$formatNumber(2.675, '0.00')` is `2.68` where CPython writes `2.67`, as `$round` does. A picture writes a negative number with the sub-picture after its `;`, so `'00000;-0000'` fills to five characters with the sign inside them, as Python's `d` counts it (`$formatNumber(-12, '00000;-0000')` is `-0012`). A picture with no digits after the decimal point drops the fraction (`$formatNumber(1234.5, '#,##0')` is `1,234`), and a number past the digits a double holds is written as the decimal it is written as, not as the double's own digits (`$formatNumber(1e308, '0.00')` is 1 and 308 zeros; measured). jsonata-python rounds the double instead, giving `0.13`, `3` and `2.67`, so `sfnx.testing` replaces the function for the pictures the compiler writes.
- `$pad` fills on the right for a positive width and on the left for a negative one, repeating a fill of several characters and taking a width of 6.5 as 6. It counts the width in code points, as `$length` does, so text outside the Basic Multilingual Plane is filled to the width Python fills it to, and a fill that is such a character counts as one (measured).
- `$distinct` keeps the first of each value in order, compares objects and arrays by value, and keeps `true` apart from `1`; `$zip` stops at the shortest array (measured).
- `$hash` gives the lowercase hex digest of the UTF-8 text for `MD5`, `SHA-1`, `SHA-256`, `SHA-384` and `SHA-512`; `$partition` returns nothing for an empty array and for a size of 0, makes batches of one item for a size of 1.5, and fails below 0 (measured).
- Given undefined, the added functions return nothing rather than fail: `$parse` with no text or undefined, `$hash` with undefined text or no algorithm, `$partition` with undefined items, and `$range` with fewer than three arguments or any of them undefined. `$partition` with no size or an undefined one makes the whole array one batch (`[[]]` for an empty one). `$hash` fails on an undefined algorithm and on any spelling but those five (`sha-256`, `SHA256`), and `$parse(null)` fails (measured).
- The added functions check their arguments: one too many, or one of the wrong type (`null`, a number for text, text for a number, a boolean), fails with `T0410`, as `$uuid` does with any argument, `$hash()` with none, and `$random` with a seed that is not a number. `$partition` fails on items that are not an array (`T0412`) and on a size below 0; `$range` and `$partition` cut a fraction to a whole number toward zero (`$range(-1.5, 2.5, 1)` is `[-1, 0, 1, 2]`), and a step or size that becomes 0 gives nothing. `$random(seed)` gives the same number for the same seed (measured, and recorded on AWS by tiny-asl-machine's conformance tests).
- `$formatNumber`, `$base64decode` and `$decodeUrlComponent` give nothing for undefined and fail with `T0410` on a value of the wrong type; `$fromMillis` gives nothing for undefined or text (`$fromMillis('a')`). `$now` and `$fromMillis` read the timezone `utc` as UTC, where jsonata-python fails on it (measured); `sfnx.testing` reads any timezone that is not `±HHMM` that way.
- `$range` gives its numbers as a sequence, as a path does: none is undefined and one is that number (`$range(1, 9, 9)` is `1`), while `[$range(...)]` is always an array (measured). `$partition` keeps a single batch in an array (`$partition([1], 1)` is `[[1]]`; measured).
- `$base64encode` and `$base64decode` read and write the text as UTF-8; `$base64decode` takes text missing its padding (`'YWJ'` is `"ab"`) and fails on a character outside the alphabet (measured).
- `$decodeUrlComponent` reads `+` as a space, fails on a malformed escape such as `%zz` (`D3140`), and gives U+FFFD for a broken UTF-8 sequence such as `%E6` (measured). jsonata-python keeps the `+` and passes `%zz` through, so `sfnx.testing` replaces the function.
- `$split` with a string separator splits at that exact text (`.` and `*` are not patterns), keeps empty parts, and splits into characters at `''` (measured).
- `$trim` turns every run of whitespace into one space and removes it from both ends: `$split($trim('  a  b\t\nc '), ' ')` is `["a", "b", "c"]`, and `[""]` for blank text (measured).
- `$replace` with a string pattern takes `$0` in the replacement literally, fails on an empty pattern and on a negative limit, replaces nothing with a limit of 0, and takes a limit of 2.5 as 2 (measured).
- `$replace` also takes a regular expression written between slashes, and Step Functions reads `\s` in one as the ASCII whitespace: `$replace($s, /^\s+|\s+$/, '')` leaves a non-breaking space or an ideographic space at an end, which jsonata-python and Python's `strip()` remove (measured).
- `$string` gives a string back as it is, and writes one inside an array or an object with the quotes and escapes of JSON. `$string([$x])` is no way to quote one, as an array `$x` is spliced into the brackets (`[1,2]`, not `[[1,2]]`); `$string({'v': $x})` keeps the value whole, and `$replace` with `/^\{"v":|\}$/` takes the value's own text out of it, emoji included, where `$substring` miscounts. It writes no spaces, and with `true` as its second argument it writes each member on a line of its own, indented by two spaces, as CPython's `json.dumps(x, indent=2)` does. It writes a whole number below 1e21 in its digits (`1.0` as `1`, `1.5e16` as `15000000000000000`) and a larger one in exponent notation (`1.5e+21`), and rounds any other number down to 15 significant digits, without trailing zeros, in exponent notation from 1e-7 down and wherever the digits end before the decimal point: `0.6666666666666666` is `0.666666666666666`, `-0.6666666666666666` is `-0.666666666666667`, `0.00000015` is `1.5e-7` and `1234567890123456.7` is `1.23456789012345e+15`. It escapes the quote, the backslash, `\b`, `\f`, `\n`, `\r` and `\t`, and writes every other character as it is, U+0001, U+2028, `é` and `😀` among them (measured). jsonata-python escapes every character outside ASCII and every control character as `\uXXXX`, and writes the numbers in an array or an object as CPython does (`1.0`, `1e-07`, `0.30000000000000004`), so `sfnx.testing` replaces the function.
- `$join` of `[]` is `""`, of a string is that string, and of an array holding a non-string fails (measured).
- `$lowercase` and `$uppercase` changed `İ`, `ẞ`, `Σ`, `ß`, `ǆ` and `ﬁ` as Python's `lower()` and `upper()` do (measured).
- `$substring` counts a negative start in UTF-16 units in Step Functions but in code points in jsonata-python (`$substring('héllo😀', -1, 1)`); `$length` counts code points in both (measured). On text with characters outside the Basic Multilingual Plane, Step Functions also returned other characters or half of one for some positive positions and lengths (`$substring('a😀b', 1, 1)`), and without a length it failed at 30 of 35 starts, where with a length it failed at none (measured).
- `$substring` with a negative start past the beginning starts at the beginning and takes the length from there (`$substring('hello', -10, 2)` is `"he"`); a negative length gives `""` (measured).
- `$round` rounds half to even at the decimal digits of the number (`$round(2.5)` is `2`, `$round(2.675, 2)` is `2.68`), and a negative number of digits rounds to tens and beyond (`$round(25, -1)` is `20`). `$ceil(-1.5)` is `-1` and `$floor(-1.5)` is `-2`, and `$sqrt` fails on a negative number (measured).
- `$sum([])` is `0`; `$max([])`, `$min([])` and `$average([])` return nothing. `$sum` and `$max` failed on an array holding a string and took a number outside an array as a one-item array (measured).
- `$reduce` takes a function of the value carried and the item, and of an empty array gives the initial value; a conditional evaluates only the branch it takes, so `$error()` in the other branch does not run (measured).
- `$lookup` of a missing key returns nothing, and Step Functions rejects `??` and `?:` when it validates a definition; `$exists($d.k) ? $d.k : null` gives null for a missing key and the value, null included, for a present one (measured).
- `$keys` returns the one key of an object as itself and nothing for an empty object; `$each` does the same with the results of its function, and returns a single result that is an array as that array (measured).
- `$split($s, '')` splits a character outside the Basic Multilingual Plane into two items, neither of them the character (measured).
- `$sort` without a function orders an array of numbers or of strings and fails on booleans, arrays and mixed items; it orders strings by UTF-16 units. `$reverse` and `$sort` return an array for any number of items (measured).
- `$sort` with a function of two parameters orders by it, and in Step Functions it leaves items the function calls equal in the order they came, as Python's `sorted` does; jsonata-python reorders them, so a test cannot tell the two apart. `$max` and `$min` take no function of their own, and `$sort(...)[-1]` and `$sort(...)[0]` are what read the greatest and the least (measured).
- `[a..b]` is an array for any number of items, empty when `b` is less than `a`. `$range(a, b, step)` includes `b` when a step reaches it and returns one number as itself and none as nothing (measured).
- `$xs[[a..b]]` returns the item itself for a range of one position and undefined for an empty range, while `$filter` passes each item's position as the second parameter of its function (measured).
- A block binds variables for the expressions after them: `($s := $states.input.code; $pad($s, -5, "0"))` works in Step Functions (measured).
- `Comment` is accepted at the top level, on every state type, and on Choice rules, retriers, catchers, Parallel branches and Map processors (measured).
- Variable names are Unicode identifiers (ID_Start, then ID_Continue), at most 80 characters; `$states` is reserved. Non-ASCII names work (measured).
- A string is evaluated when it starts with `{%` and ends with `%}`, including strings inside objects and arrays; a half-open one fails validation. One that does not parse fails validation too (`INVALID_JSONATA_EXPRESSION`), inside an `Arguments` or an `Assign` key named `Comment` as well, but not in the `Comment` of a state, a Choice rule or a catcher (measured).
- `$states` has `input` and `context` everywhere, `result` in the `Assign` and `Output` of a Task, a Parallel and a Map, and `errorOutput` in those of a catcher. Reading another field by name fails validation (`UNSUPPORTED_JSONATA_EXPRESSION`), as `$states.result` in a Pass or in a Task's `Arguments` does. Validation looks at a path that starts at `$states`, so `$states.result[0]` and ``$states.`result` `` fail but `($states).result` and `$states['result']` pass (ValidateStateMachineDefinition; measured).

### States

- A state is in its own `QueryLanguage`, or else in the definition's, which is JSONPath when the definition leaves it out. A state in a Parallel branch or a Map reads the definition's, not the Parallel's or the Map's: under a definition without it, a Map set to JSONata runs its processor's states in JSONPath unless each sets JSONata. A state cannot set JSONPath in a definition set to JSONata (ValidateStateMachineDefinition; measured).
- State names must be unique across the whole definition, branches and Map processors included (`DUPLICATE_STATE_NAME`; measured). A distributed Map `Label` must be unique too (`DUPLICATE_LABEL_NAME`; measured).
- Only Parallel and Map create scopes. An inner scope can read outer variables but cannot assign a name the outer scope assigns on the way into the Parallel or the Map, inline or distributed (`DUPLICATE_VARIABLE_NAME`; measured). On the way means the `Assign` of a transition that leads to the state, loops included: a state's own for its `Next` or `Default`, a Choice rule's and a catcher's own. A name the outer scope assigns only after the state, in the state's own `Assign` or in its catcher, is free (ValidateStateMachineDefinition; measured). A Catch's `Assign` writes to the outer scope. A distributed Map reads no outer variables.
- Choice evaluates its rules in order and fails if none holds and there is no `Default`. A Choice has no `End`. A rule that matches assigns and outputs by its own `Assign` and `Output`, not by the state's, which run only when the `Default` is taken; without an `Output`, the input goes on (measured; corpus: `choice-rule-assigns-by-its-own-assign`, `choice-default-assigns-by-the-states-assign`).
- A Task's `Assign` and `Output` are evaluated when it ends, and a Wait's `Assign` and `Output` when the wait is over: `$millis()` there was 276 ms after an activity worker sent its result, 3,035 ms after a 3-second Wait was entered in its `Assign` (Standard execution), and 2,000 ms after a 2-second Wait's `EnteredTime` in its `Output` (Express execution; measured).
- The `Assign` and `Output` of a Pass, a Wait, a Choice rule and a catcher read the variables from before the state, as a Task's do; a catcher's also read `$states.errorOutput` and `$states.input` (measured; corpus: `catch-reads-what-was-assigned-before`, `catch-in-a-map-reads-the-error`). A Parallel's `Arguments` is the input of every branch (measured).
- Only Task, Parallel and Map have `Retry` and `Catch`. A Fail has `Error` and `Cause`, which may be expressions, and no `Assign`.
- `Output` takes any JSON value, null included.
- JSONata states have no `InputPath`, `Parameters`, `ResultSelector`, `ResultPath`, `OutputPath` or `*Path` fields (`SecondsPath`, `ItemsPath`), and no intrinsic functions; `Arguments`, `Output` and expressions take their place.
- Written in the definition, Wait `Seconds` is a whole number from 0 to 99,999,999, and `Timestamp` is RFC 3339 with an uppercase `T` and `Z`. What an expression gives them at run time is read more widely: `Seconds` takes `0.0`, and was still waiting on 100,000,000 after 20 seconds rather than failing, but fails on a negative number, `1.5`, a string, `null` or a boolean; `Timestamp` takes a lowercase `t` or `z`, an offset such as `+09:00`, no seconds, or nine digits of a fraction, but fails on a space for the `T`, no offset, a date that does not exist (`2016-02-30`) or a number. Each failure is `States.QueryEvaluationError` (TestState; measured).
- An inline Map's `Items` is an array; a distributed Map's may be an object. Any other value an expression gives `Items`, an object for an inline Map included, fails with `States.QueryEvaluationError`. Without `Items`, a Map iterates its input, which must be an array, and without `ProcessorConfig` it is inline (recorded on AWS by LocalStack's Step Functions tests). A distributed Map needs `ProcessorConfig.ExecutionType`; its `Label` is at most 40 characters without whitespace, wildcards, brackets or special characters. With `ItemBatcher`, a child's input is `{"Items": [...], "BatchInput": {...}}`, each item as the `ItemSelector` selects it, which is evaluated for each item before the items are batched (TestState; measured).
- For an object of items, `Map.Item.Key` is an entry's key and `Map.Item.Value` its value; without an `ItemSelector`, a child's input is `{"Key": ..., "Value": ...}` (measured).
- With a `ResultWriter`, whose `Arguments` need `Prefix`, a distributed Map's result is `{"MapRunArn": ..., "ResultWriterDetails": {"Bucket": ..., "Key": "<Prefix>/<run>/manifest.json"}}`, with or without `WriterConfig` (measured).
- A failed child execution of a distributed Map fails the Map with `States.ExceedToleratedFailureThreshold`, not with the child's error, unless the failed items are within `ToleratedFailureCount` (at most the count) or `ToleratedFailurePercentage` (at most that share of the items). A tolerated child takes its place in the result as `{"Status": "FAILED", "Error": ..., "Cause": ...}` (measured). With both thresholds, exceeding either fails the Map, as documented, but a threshold of 0 counts as not set: a count of 0 with a percentage that held did not fail (measured). With `ItemBatcher`, a failed batch counts each of its items and takes one place in the result (measured).
- The Context Object has `Execution` (`Id`, `Input`, `Name`, `RoleArn`, `StartTime`, `RedriveCount`, `RedriveTime`), `State` (`EnteredTime`, `Name`, `RetryCount`), `StateMachine` (`Id`, `Name`) and `Task` (`Token`). `RedriveCount` is 0 in an execution never redriven, which has no `RedriveTime` (measured). `State.RetryCount` exists in a Task and a Map, and in a Parallel's `Arguments`, not in a Pass or a Succeed; it is the number of retries before the current attempt, and in a Catch's `Assign` the number of retries made; a retry of a Map evaluates its `Items` again (measured; corpus: `map-retry-evaluates-the-items-again`). A child execution of a distributed Map has its own `Execution.Id` and `Name`, and its `StateMachine.Id` ends in `/<map run>` (measured). `Map.Item` is readable only in the `ItemSelector`.
- A Standard execution's history holds 25,000 events, and every state transition is billed. Express executions are billed by their number, duration and memory instead.

### Errors

- Error names starting with `States.` are reserved. `States.TaskFailed` matches every error except `States.Timeout` and `States.QueryEvaluationError`: the documentation names only `States.Timeout`, but a Retry or a Catch for `States.TaskFailed` let the `States.QueryEvaluationError` of a Task's `Arguments`, `Assign` or `Output` through (TestState; measured). `States.ALL` stands alone in the last retrier or catcher.
- `States.Runtime` cannot be retried or caught.
- A Parallel whose branch ends in a Fail fails with the Fail's `Error` and `Cause`, not with `States.BranchFailed`: a retrier and a catcher for `States.BranchFailed` did not match it, where a retrier for the Fail's error and catchers for that error and for `States.TaskFailed` did (Express execution; measured). sfnx does not export `BranchFailed`, since a retrier for it would not run where a branch raises.
- A retrier's attempts add up over all the errors it matched in the state. Only the first retrier that matches an error counts it: once that one has no attempts left, the error is not retried even if a later retrier matches (TestState; measured). A failure in evaluating `Arguments`, `Assign` or `Output` is retried as a failure of the Task by a retrier for `States.QueryEvaluationError` or `States.ALL` (TestState; measured).
- The documentation says `States.ALL` does not catch `States.DataLimitExceeded`, but one raised by an SDK integration result over the quota (`ec2:describeImages` with `Owners: ["amazon"]`) was caught by both `States.ALL` and `States.TaskFailed`, in TestState and in Standard and Express executions (measured). Other causes were not measured.
- A Lambda function's error name is its exception type, and its `Cause` is JSON written by the runtime (measured).
- An SDK integration's `Arguments` and result are spelled with the member names of the AWS SDK for Java v2, capitalized: `DbInstanceIdentifier`, `Acl`, `SsekmsKeyId`, `SseCustomerKeyMD5`, `MultiAZ`, `QueueOwnerAWSAccountId`, and in a DynamoDB attribute value `Bool` and `Ss`, where botocore has `DBInstanceIdentifier`, `ACL`, `SSEKMSKeyId`, `SSECustomerKeyMD5`, `BOOL` and `SS`, and nested keys follow the same rule (`AwsvpcConfiguration` for ECS's `awsvpcConfiguration`). TestState rejects the botocore spelling with the SDK's as the one it meant, and `rds:describeDBEngineVersions` returned `DbEngineVersions` and `DbParameterGroupFamily` (measured). ValidateStateMachineDefinition takes an unknown key where the argument is not required, so it does not catch a wrong spelling. An optimized integration takes botocore's names with the first letter capitalized: `BOOL` and `AwsvpcConfiguration`, not `Bool` (measured).
- An SDK integration's error name is the class the AWS SDK for Java throws, after the service's name in that SDK: `Sqs.QueueDoesNotExistException` for the shape botocore names `QueueDoesNotExist` (error code `AWS.SimpleQueueService.NonExistentQueue`), `Sfn.InvalidArnException`, `S3.NoSuchBucketException`, `CloudWatchLogs.AccessDeniedException`, and for an error the model does not list, such as access denied, the service's own class: `DynamoDb.DynamoDbException`, `Rds.RdsException`, `Ec2.Ec2Exception`, `ElastiCache.ElastiCacheException`, `ApiGateway.ApiGatewayException`, `Lambda.LambdaException` (TestState; measured). The compiler derives both names from botocore's model by the rules of the SDK's code generator (`DefaultNamingStrategy`): the service ID and the shape are cased word by word (`DynamoDB` is `DynamoDb`, `DBInstanceNotFoundFault` is `DbInstanceNotFoundException`), a trailing `Fault` becomes `Exception`, and the few shapes the SDK renames (Elastic Load Balancing's `AccessPointNotFoundException` is `LoadBalancerNotFoundException`) are listed. The service's name in lowercase is the one its resource ARN takes, for every botocore service but `sms-voice`, which shares its service ID with `pinpoint-sms-voice`.

### Tasks

- An SDK integration's resource is `arn:aws:states:::aws-sdk:<service>:<action>`, where the service follows the AWS SDK for Java (`sfn`, `eventbridge`, `cloudwatchlogs`) and the action is camelCase. Its arguments are PascalCase even for camelCase APIs, and so is its result, nested fields included (`logGroups[].arn` is `LogGroups[].Arn`); timestamps arrive as strings (measured).
- ValidateStateMachineDefinition rejects an SDK integration without `Arguments` (`{}` is needed), a resource that still contains `${...}`, and unknown keys and missing idempotency tokens of SDK integrations (measured). `Arguments` written as one expression, such as `$merge`, passes for SDK integrations and HTTP Tasks (measured). For the 16 optimized actions whose botocore model the compiler checks against, it rejected an unknown key, rejected some keys botocore has, and required some that botocore makes optional (measured). It rejects the resource of an action botocore has and the documentation lists as unsupported (`s3:selectObjectContent`, `sts:assumeRole`, `lambda:invokeWithResponseStream`, `bedrockruntime:converseStream`, `cloudwatchlogs:startLiveTail`, `kinesis:subscribeToShard`) and of a service botocore has and the documentation does not list (`cloudsearchdomain`, `mediastoredata`, `iotjobsdata`) as not recognized, as it rejects an action that does not exist (`SCHEMA_VALIDATION_FAILED`; measured in ap-northeast-1). The diagnostic also names a resource not available in the region, so the check holds for the region it is run in.
- ValidateStateMachineDefinition checks the types of literal argument values: a Lambda `Payload` takes a string, object, array or null, and rejects a number or boolean literal. Expressions pass (measured).
- `TimeoutSeconds` is a whole number from 1, `HeartbeatSeconds` a smaller one. `Credentials` applies only to Lambda functions and AWS service integrations. An HTTP Task needs `ApiEndpoint`, `Method` and a connection, and stops after 60 seconds.
- botocore has no service model whose service ID disagrees with the AWS SDK for Java name; loading every model takes about four seconds.

### Programs as a whole

Programs from the generator in `tests/test_differential.py` were run in Step Functions and compared with CPython (errors by name): 40 without tasks as Express executions, and 40 with Lambda tasks, 10 of them with distributed maps as Standard executions, each with three inputs. All 240 runs agreed (measured).

The fixed cases of `tests/corpus.py` are the edges the generator avoids, and `tests/aws_corpus.py` runs them in Step Functions on request; [verification.md](verification.md) says what each check guarantees.
